### a3e_fnc_BuildPrison  —  `Code/functions/Templates/fn_BuildPrison.sqf`  ·  _status: documented_
- **Purpose:** One of six interchangeable prison "start position" layouts where captured players begin. This variant is an **open compound**: a ring of `Land_HBarrier_*` (H-barrier) walls around a courtyard, entered through a large `Land_City_Gate_F`, with a campfire/camping-chairs sitting area, flagpole, and floodlit generator corners. Map Builder export. See `a3e_fnc_BuildPrison1` for the full shared-contract writeup; this entry notes only how it differs.
- **Inputs:** `params ["_center","_rotation","_backpack"]` — `_center` = compound origin (`A3E_StartPos`), `_rotation` = random 0–360 fence heading, `_backpack` = pre-spawned loot backpack object. Reads global `A3E_VAR_Flag_Ind` (independent-side flag texture). Same as all variants.
- **Outputs:** No return value. Server-side sets globals `A3E_PrisonLoudspeakerObject` (publicVariable'd) and `A3E_PrisonGateObject` (plain global, NOT broadcast). Side effects: `cleanupTerrain` clears 25 m; global `createVehicle` for gate + loudspeaker; ~50 `createVehicleLocal` objects (H-barriers, ClutterCutters, flagpole, campfire, camping chairs, cans, portable lights, generators) duplicated per client. No guards, captives, markers, or cleanup handle.
- **Calls:** `a3e_fnc_cleanupTerrain` (`[_center,25]`), `A3E_fnc_rotatePosition` (once per object, to rotate the exported local offset around `_center` by `_rotation`). Engine: `createVehicle` / `createVehicleLocal`, `setVectorDirAndUp`, `setDir`, `setPosATL`, `setFlagTexture`.
- **Called by:** [template-array] `A3E_PrisonTemplates` (`Mods/*/UnitClasses.sqf`, default in `Server/fn_createStartpos.sqf:5`), selected via `selectRandom` and invoked with `remoteExec [_template, 0, true]` (dynamic dispatch — runs on all machines + JIP). Not a direct `fnc_` caller; the `_xref` `## Templates` section will show "no references found".
- **Processing:** (1) `if(isserver)`: `cleanupTerrain`; place `_backpack` at `_center` + random ±1 m jitter; `createVehicle` the loudspeaker (`Land_Loudspeakers_F`) → `A3E_PrisonLoudspeakerObject` + publicVariable; `createVehicle` the gate (`Land_City_Gate_F`) → `A3E_PrisonGateObject`. (2) All-machine block: for each exported object, `rotatePosition` the offset, `createVehicleLocal`, then `setVectorDirAndUp` + `setDir (+_rotation)` + `setPosATL`. Ends after last generator; no return statement.
- **Theory of operation:** Identical mechanism to `BuildPrison1` (see there). Distinguishing detail: this is the only variant with **no roofed building** — captives start in an open H-barrier pen rather than a shed/slum house — and the gate is the vanilla `Land_City_Gate_F` swing gate (not a TinWall gate). The gate here is **not** `allowDamage false` (unlike the Tin/Slum variants), so it can be destroyed.
- **Whys & questions:** Same open questions as `BuildPrison1`. Additional: gate lacks `allowDamage false` — inconsistent with siblings; whether that is intentional (destructible escape route) or an oversight is unclear (candidate Q). H-barriers are RHS/CUP-independent vanilla assets, so this layout is broadly mod-portable.
- **Unresolved issues:** Shares the family-wide issues from `BuildPrison1` (no despawn/cleanup of ~50 local objects; `A3E_PrisonGateObject` never broadcast; per-object `rotatePosition` calls). Gate not damage-protected (see Whys). Candidate RD: near-total structural duplication across the six files.
- **Reforger port notes:** Represent as an Enfusion prefab/composition placed at the start position with a random yaw, rather than 50 scripted spawns. H-barrier + gate + props map to World Editor entities. Gate-open detection (consumed in `fn_initServer`) becomes a door/trigger event in Enfusion. See `BuildPrison1` for the general porting strategy.

### a3e_fnc_BuildPrison1  —  `Code/functions/Templates/fn_BuildPrison1.sqf`  ·  _status: documented_
- **Purpose:** Representative entry for the BuildPrison family. One of six interchangeable prison start-position layouts where captured players spawn at mission start. Each is a Map-Builder-exported object composition that assembles a small fortified compound around a central holding structure. This variant ("Tin Shed with metal gate center wall") builds a `Land_Shed_07_F` tin shed enclosed by `Land_TinWall_01_m_*` walls with a `Land_TinWall_01_m_gate_v1_closed_F` gate, ringed by `Land_SandbagBarricade_01_half_F` sandbags, plus a flagpole, loudspeaker, and two `MetalBarrel_burning_F` barrels.
- **Inputs:** `params ["_center","_rotation","_backpack"]`. `_center` = world position of the compound origin (`A3E_StartPos`); `_rotation` = random heading 0–360 (`_fenceRotateDir` from the dispatcher) applied uniformly so the whole prison faces a random direction each session; `_backpack` = a loot backpack object already `createVehicle`'d by the dispatcher (a starting weapon/gear cache for the escapees). Reads global `A3E_VAR_Flag_Ind` for the flag texture. `_obj`/`_pos` are declared `private`.
- **Outputs:** No return value (last statement is an object placement). Server-side global state: `A3E_PrisonLoudspeakerObject` (set + `publicVariable` — later used for prison-announcement audio) and `A3E_PrisonGateObject` (set as a plain global, consumed server-side in `fn_initServer.sqf:647-649` to detect the gate being opened via door `animationPhase`). Side effects: `cleanupTerrain` flattens/clears 25 m radius; `_backpack` repositioned with ±1 m jitter; one global loudspeaker + one global gate created; ~35 local props created on every machine. **No guards, no captive/player spawn positions, no markers, and no despawn/cleanup handle are created here.**
- **Calls:** `a3e_fnc_cleanupTerrain` (`[_center,25] call`, server only). `A3E_fnc_rotatePosition` (`[_center, _center vectorAdd <offset>, _rotation] call`, once per object — converts the Map-Builder local offset into a world position rotated about `_center`). Engine commands: `createVehicle` (global, server block only), `createVehicleLocal` (all machines), `setVectorDirAndUp`, `setDir`, `setPosATL`, `setFlagTexture`, `allowDamage`.
- **Called by:** [template-array] `A3E_PrisonTemplates`, selected in `Server/fn_createStartpos.sqf` (dynamic dispatch) — not a direct `fnc_` caller; the `_xref` `## Templates` section will show "no references found". Concretely: `fn_createStartpos.sqf:5` does `selectRandom A3E_PrisonTemplates` then `fn_createStartpos.sqf:7` `[A3E_StartPos, _fenceRotateDir, _backPack] remoteExec [_template, 0, true]` — so the chosen builder runs on the server **and every client** (JIP-persistent), which is why the split of global-vs-local object creation exists.
- **Processing:**
  1. `params`; declare `_obj`/`_pos`.
  2. **Server-only block** (`if(isserver)`): `[_center,25] call a3e_fnc_cleanupTerrain`; create the loudspeaker with global `createVehicle`, store `A3E_PrisonLoudspeakerObject` and `publicVariable` it; create the gate (`...gate_v1_closed_F`) with global `createVehicle`, `allowDamage false`, store `A3E_PrisonGateObject`; reposition `_backpack` at `_center` + random ±1 m jitter with `_rotation`-adjusted heading.
  3. **All-machine block:** a long flat sequence of object placements via `createVehicleLocal`. Each block: `_pos = [_center, _center vectorAdd <exported-offset>, _rotation] call A3E_fnc_rotatePosition;` → `createVehicleLocal _pos` → `setVectorDirAndUp <exported-basis>` → `setDir ((getDir _obj) + _rotation)` → `setPosATL _pos`. Structural pieces (`Land_Shed_07_F`, `Land_TinWall_01_m_4m_v1_F`) get `allowDamage false`. Props: sandbag barricades, ClutterCutters (grass hiders), flagpole (`setFlagTexture A3E_VAR_Flag_Ind`), two burning metal barrels.
- **Theory of operation:** These templates are pure "dumb geometry" placers produced by exporting a composition from the Map Builder tool; the mission substitutes a runtime `_center`/`_rotation` so the same static layout can appear anywhere at any heading. Splitting **server-global** objects (gate, loudspeaker) from **client-local** objects (`createVehicleLocal`) is a deliberate network optimization: only the two objects the game logic must reference by name (gate for the open-detection door animation; loudspeaker for announcements) are network objects; the ~35 decorative pieces are recreated identically on each client from the deterministic offsets, saving start-of-mission bandwidth. `allowDamage false` on the structure/walls keeps the pen intact so the "gate opens = escape begins" mechanic stays meaningful. Running under `remoteExec [_,0,true]` with JIP ensures late joiners also build the identical local scenery.
- **Whys & questions:** Why six near-identical files instead of one data-driven builder fed an object array? Almost certainly because Map Builder exports one `.sqf` per composition and nobody refactored them — high duplication (candidate RD). Why is `A3E_PrisonGateObject` a plain global (not `publicVariable`'d) when the loudspeaker is broadcast? Because gate-open detection runs server-side only (`fn_initServer`), so clients never need the reference — intentional, but undocumented (candidate Q). Why `createVehicleLocal` for scenery but not the sandbags being persistent? Bandwidth; the tradeoff is that local objects cannot be despawned/tracked centrally later.
- **Unresolved issues:** (1) No cleanup: the ~35 local objects per client are never deleted; if the start position is ever reused/rebuilt they would leak (likely fine because start position is built once per session, but worth noting — candidate RD). (2) Hardcoded vanilla Arma 3 classnames (`Land_TinWall_01_*`, `Land_Shed_07_F`, `Land_SandbagBarricade_01_half_F`, `MetalBarrel_burning_F`) — these are base-game assets so should exist across mod configs, but any classname rename/removal would silently drop objects. (3) `A3E_PrisonGateObject` set with no nil-guard; if a variant failed to create it, `fn_initServer` guards with `isNil` so it is handled. (4) Family-wide duplication (candidate RD-dup).
- **Reforger port notes:** In Enfusion/Reforger this should become a **prefab composition** (a saved World Editor group/prefab) instantiated at the start position with a random yaw — not dozens of scripted `createVehicle` calls. The server-global vs client-local split disappears (Enfusion replication is entity-based). The gate should be a real door entity whose open state raises a script event (replacing the `animationPhase "Door_1_rot"` polling in `fn_initServer`). The loudspeaker announcement hook and the flag-texture-by-faction concept both need equivalents. Keep the "random heading + backpack cache drop + terrain flatten" behaviors as spawn-time logic on the composition.

### a3e_fnc_BuildPrison2  —  `Code/functions/Templates/fn_BuildPrison2.sqf`  ·  _status: documented_
- **Purpose:** Prison start-position layout — variant of `BuildPrison1`. Differences: "Small Tin shed with door, tin window covers, flag, speakers, burning barrel x 2 and sandbags." Central structure is `Land_Shed_05_F` (a smaller doored tin shed) used **as** the gate object; tin-wall segments and sandbags form the perimeter. Smaller than BuildPrison1 (147 vs 184 lines).
- **Inputs:** Same as `BuildPrison1`: `params ["_center","_rotation","_backpack"]`; reads `A3E_VAR_Flag_Ind`.
- **Outputs:** Same contract. Notable ordering difference: sets `A3E_PrisonGateObject` = the `Land_Shed_05_F` **before** creating/broadcasting `A3E_PrisonLoudspeakerObject` (order within the server block is swapped vs BuildPrison1, no functional effect). No guards/captives/markers/cleanup.
- **Calls:** Same as `BuildPrison1` — `a3e_fnc_cleanupTerrain`, `A3E_fnc_rotatePosition`, engine placement commands.
- **Called by:** [template-array] `A3E_PrisonTemplates`, selected in `Server/fn_createStartpos.sqf` (dynamic dispatch) — not a direct `fnc_` caller; the `_xref` `## Templates` section will show "no references found".
- **Processing:** Same three-phase shape as `BuildPrison1` (server global block: cleanup + shed-as-gate + loudspeaker + backpack jitter; then all-machine `createVehicleLocal` sequence of tin walls, sandbags, ClutterCutters, flagpole, burning barrels). Differs only in the specific objects/offsets. `Land_Shed_05_F` gets `allowDamage false`.
- **Theory of operation:** Identical to `BuildPrison1`; here the "gate" the players must pass is the shed's own door (the shed doubles as holding cell + exit), which is why the shed itself is stored as `A3E_PrisonGateObject` for the open-detection logic.
- **Whys & questions:** Same as `BuildPrison1`. Additional: using a whole building as the "gate" means gate-open detection depends on `Land_Shed_05_F` having door animation sources named like the poll in `fn_initServer` (`Door_1_rot`/`Door_2_rot`) — worth verifying that class exposes those (candidate Q).
- **Unresolved issues:** Shares family-wide duplication + no-cleanup + hardcoded-classname issues (see `BuildPrison1`). Gate-detection-on-a-building assumption noted above.
- **Reforger port notes:** Same as `BuildPrison1`; the shed-as-gate merely means the door entity that raises the open event is the shed's own door.

### a3e_fnc_BuildPrison3  —  `Code/functions/Templates/fn_BuildPrison3.sqf`  ·  _status: documented_
- **Purpose:** Prison start-position layout — variant of `BuildPrison1`. Differences: "Tin Shed, tin gate off center, tin walls, flag, speakers, burning barrels x 2 and sandbags." Uses a dedicated `Land_TinWall_01_m_gate_v1_closed_F` tin gate (server-global, the `A3E_PrisonGateObject`) plus a `Land_Metal_Shed_F` interior structure and tin-wall/sandbag perimeter.
