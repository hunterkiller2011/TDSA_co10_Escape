### AIskills.sqf  —  `Code/Scripts/Escape/AIskills.sqf`
- **Purpose:** Defines the global function `EGG_EVO_skill` that sets an AI unit's skill sub-values from a single 0–6 difficulty tier (Cadet…Extreme, plus a "manual settings" tier that reads `paramsArray`), and a tier 6 pass-through for external AI mods (Zeus AI etc.).
- **Inputs:** `_this = [_unit, _skill]` where `_skill` is an integer 0–6. Reads global `paramsArray` (mission parameter array) for tier 5. The header comment shows the intended call as `[_guard, 3] spawn call EGG_EVO_skill` (see Whys — that syntax is wrong).
- **Outputs:** Side effect only — `setSkill` and per-attribute `setSkill [...]` on `_unit` (general, aimingAccuracy/Shake/Speed, endurance, spotDistance, spotTime, courage, reloadSpeed, commanding). No return value. Defines the global `EGG_EVO_skill` (code value) in `missionNamespace`.
- **Calls:** Engine `setSkill` only; no A3E/DRN callees.
- **Called by:** Loaded once on the server via `call compile preprocessFileLineNumbers "Scripts\Escape\AIskills.sqf";` at `Code/functions/Server/fn_initServer.sqf:13` (so `EGG_EVO_skill` becomes globally defined). **However every actual invocation of `EGG_EVO_skill` in the codebase is commented out** — e.g. `CreateReinforcementTruck.sqf:60,70`, `CreateMotorizedSearchGroup.sqf:52,63`, `EscapeSurprises.sqf:157,203`, `fn_initServer.sqf:569`, and several `Code/functions/DRN/*`. So the function is defined-but-dead.
- **Processing:** For `_skill < 5`: a `switch` maps the tier to `_aiSkillBase` (0.2 / 0.5 / 1.0 / 1.4 / 1.8), then scales each attribute by fixed multipliers. For `_skill == 5`: reads ten values out of `paramsArray` (indices 8–17) instead. Tier 6 (and any value ≥6 that isn't 5) falls through and does nothing — the "use an AI mod" case, deliberately leaving skills untouched.
- **Theory of operation:** Centralizes the mission's older per-unit skill model behind one call so spawners could tune difficulty uniformly. It has been superseded — the live path sets skill through `A3E_fnc_onEnemySoldierSpawn` (invoked via `drn_fnc_Escape_OnSpawnGeneralSoldierUnit`, defined in `Functions.sqf`), which is why the `EGG_EVO_skill` calls were commented out everywhere.
- **Whys & questions:** `_aiSkillBase = 1.0` is initialized then immediately overwritten in the switch — harmless. The header example `[_guard,3] spawn call EGG_EVO_skill` is malformed SQF: `spawn call X` is nonsensical (you `spawn X` or `call X`, not both). This is a comment, not executed code, but signals the original author's uncertainty.
- **Unresolved issues:** Effectively dead code — defined at init but no live caller. Candidate for removal, or for re-wiring if a Reforger port wants tiered skill. The `paramsArray` indices (8–17) are brittle magic numbers tied to the old params layout; if `params.hpp` order changed, tier 5 would set wrong attributes.
- **Reforger port notes:** Enfusion AI does not use Arma 3's `setSkill` attribute model; there is no direct equivalent. In Reforger, AI competence is driven by `SCR_AICombatComponent` / perception & aiming config and difficulty presets. This file should be dropped and difficulty re-expressed via Reforger's AI config — carry over the *intent* (5 difficulty tiers + accuracy/spotting scaling), not the API.

### CivilEnemy.sqf  —  `Code/Scripts/Escape/CivilEnemy.sqf`
- **Purpose:** Drives a disguised-enemy civilian vehicle: repeatedly picks a random nearby road position and drives the crew group there in SAFE/BLUE behaviour until any member spots an enemy, at which point the group dismounts and runs an "on unload" callback (a search group).
- **Inputs:** `_this = [_referenceGroup, _vehicle, _group, (_fncOnUnloadGroup={}), (_debug=false)]`. `_referenceGroup` is the player group used as the reference for finding roads; `_vehicle` must have a `vehicleVarName` set. Reads `drn_ReinforcementTruck_CurrentEntityNo` (shared counter) and `a3e_var_commonLibInitialized`.
- **Outputs:** Adds MOVE waypoints to `_group`; sets vehicle fuel to 0.3–0.9; toggles `_vehicle` variable `waypointFulfilled`; increments `drn_ReinforcementTruck_CurrentEntityNo`. On detection: `unassignVehicle`/`orderGetIn false` all units and `_group spawn _fncOnUnloadGroup`. Creates/deletes debug markers via CommonLib when `_debug`.
- **Calls:** `drn_fnc_CL_ShowDebugTextAllClients`, `drn_fnc_CL_SetDebugMarkerAllClients`, `drn_fnc_CL_DeleteDebugMarkerAllClients` (all DRN CommonLib); engine `nearRoads`, `findNearestEnemy`, waypoint commands.
- **Called by:** `execVM "Scripts\Escape\CivilEnemy.sqf"` from `CreateCivilEnemy.sqf:44` (which is itself launched from the `CIVILIANENEMY` surprise in `EscapeSurprises.sqf:350`). Live (CIVILIANENEMY surprise is scheduled unconditionally).
- **Processing:** `exitWith` if not server. Parses args. `_fnc_GetDestinationPos` picks a random segment from `nearRoads 1250` of the reference unit. Assigns an entity number. Warns forever in a spawned loop if CommonLib isn't initialized; exits if the vehicle has no var name. Main loop while `!_enemySighted`: reset `waypointFulfilled`, get a destination, add a MOVE/SAFE/NORMAL/BLUE waypoint whose completion statement sets `waypointFulfilled` on the named vehicle, set random fuel, then inner loop sleeping 1s checking each unit's `findNearestEnemy` until the waypoint completes or an enemy is sighted. On sighting: dismount and hand off to `_fncOnUnloadGroup`.
- **Theory of operation:** Simulates an enemy infiltration cell posing as civilian traffic — it wanders the road network non-hostile until it stumbles onto players, then converts into a foot search group. The `waypointFulfilled` var + named-vehicle statement is the DRN idiom for "wake the driving loop when the car arrives."
- **Whys & questions:** Debug string and the forever-warn loop both say "ReinforcementTruck.sqf" though this is CivilEnemy — copy-paste from the DRN ReinforcementTruck template (this whole family derives from DRN CommonLib demo scripts). A large commented-out block (lines 118–171) is leftover reinforcement-truck "move out / return" logic, never used here.
- **Unresolved issues:** Reuses `drn_ReinforcementTruck_CurrentEntityNo` as its instance counter — shared with unrelated systems, so debug marker names could theoretically collide, but functionally harmless. The forever `while{true} player sideChat` CommonLib-missing warning runs on the *server* where `player` is often null — likely a no-op rather than a real warning. `findNearestEnemy` on every unit each second is cheap but the detection is coarse (any enemy, not necessarily a player).
- **Reforger port notes:** Map to an Enfusion waypoint/behavior state machine (patrol → engage) on an AI group with a civilian-classed vehicle. `nearRoads` → Reforger road/nav queries. The "poll findNearestEnemy" loop becomes a perception/target event. Drop the CommonLib debug-marker plumbing.

### CreateCivilEnemy.sqf  —  `Code/Scripts/Escape/CreateCivilEnemy.sqf`
- **Purpose:** Factory that spawns a civilian-type vehicle, gives it a unique var name, populates it with an enemy crew, applies the standard enemy-spawn hook, and hands it to `CivilEnemy.sqf` with an "on unload → SearchGroup" callback.
- **Inputs:** `_this = [_referenceGroup, _spawnPos, _side, _vehicleTypes, _unitTypes, _enemyFrequency, (_debug=false)]`. `_vehicleTypes`/`_unitTypes` are classname arrays.
- **Outputs:** Creates one vehicle (via `createVehicle [... ,"NONE"]`), assigns global var name `drn_CivilEnemyCarN`, creates an enemy group, then `execVM`s `CivilEnemy.sqf`.
- **Calls:** `drn_fnc_Escape_PopulateVehicle` (defined in `Functions.sqf`), `drn_fnc_Escape_OnSpawnGeneralSoldierUnit` (Functions.sqf → `A3E_fnc_onEnemySoldierSpawn`), `drn_fnc_CL_ShowDebugTextAllClients`; `execVM "Scripts\Escape\CivilEnemy.sqf"`. The `_fnc_OnDroppingGroup` callback does `[...] spawn drn_fnc_SearchGroup`.
- **Called by:** `execVM "Scripts\Escape\CreateCivilEnemy.sqf"` from `EscapeSurprises.sqf:350` (the `CIVILIANENEMY` surprise). Live.
- **Processing:** Server-only. Picks a random vehicle class, spawns it, finds a free `drn_CivilEnemyCarN` name by probing `isNil`, sets the name and binds the global via `call compile format`, populates the crew, applies the spawn hook to each unit, defines the search-group callback, and execVMs the driving script.
- **Theory of operation:** Separation of concerns: this is the *spawn/setup* half; `CivilEnemy.sqf` is the *behavior* half. The var-name-probe pattern lets many concurrent instances coexist and be individually referenced from waypoint statements.
- **Whys & questions:** The find-free-name loop (`while {!(isNil _vehicleVarName)}`) is a recurring DRN idiom across this family. `_index`, `_pilot` etc. are declared but not all used.
- **Unresolved issues:** None functionally; standard legacy factory. Coupled to `Functions.sqf` globals (`drn_fnc_Escape_*`) which must be loaded first (they are, at init).
- **Reforger port notes:** In Enfusion, prefer a prefab spawn + `SCR_AIGroup` population API instead of `createUnit`/`moveInCargo`. The `call compile format` global-binding trick has no Enforce Script equivalent (no runtime eval) — use entity references/handles instead.

### CreateDropChopper.sqf  —  `Code/Scripts/Escape/CreateDropChopper.sqf`
- **Purpose:** Spawns a transport helicopter with a 2-man crew (pilot + one turret gunner), loads a pre-built infantry drop group as cargo, and launches `DropChopper.sqf` to fly them to a drop position and para-eject them.
- **Inputs:** `_this = [_spawnPos, _side, _chopperType, _crewType, _dropUnits, _dropPosition, (_minSkill=0.3), (_maxSkill=0.5), (_onGroupDropped={}), (_debug=false)]`. `_dropUnits` is a pre-created array of units.
- **Outputs:** Creates the chopper (var name `drn_searchChopperN`, publicVariable'd), creates a crew group, moves drop units into cargo, then `execVM`s `DropChopper.sqf`. Increments `drn_CreateDropChopper_CurrentInstanceNo`.
- **Calls:** `A3E_fnc_Log`, `a3e_fnc_onVehicleSpawn`, `drn_fnc_Escape_OnSpawnGeneralSoldierUnit`; `execVM "Scripts\Escape\DropChopper.sqf"`.
- **Called by:** `execVM "Scripts\Escape\CreateDropChopper.sqf"` from `EscapeSurprises.sqf:176` (`DROPCHOPPER`, OPFOR) and `:222` (`DROPCHOPPER_I`, Independent). Live.
- **Processing:** Server-only. Logs, strips null units from `_dropUnits` (workaround comment). Assigns instance number. Creates chopper with `"NONE"` special, runs the vehicle-spawn hook, names+publicVariables it. `moveInCargo`/`assignAsCargo` each drop unit. Creates a crew group, spawns **two** crew units, moves unit 0 as driver and unit 1 into turret `[0]`. Sets ranks to LIEUTENANT and applies the spawn hook. execVMs `DropChopper.sqf`.
- **Theory of operation:** The "surprise" reinforcement-by-air mechanic. This is the setup half; `DropChopper.sqf` handles flight + ejection + cleanup. The crew group and drop group are distinct (drop group was created by the caller in `EscapeSurprises.sqf`).
- **Whys & questions:** Commented-out lines show the design once used three crew and `createUnit [[0,0,30], _group, ...]` (old 4-arg form) before switching to two crew and the `_group createUnit [...]` form. `_gunner2`/turret `[1]` support is disabled. `_chopperType createVehicle` (line 28) is commented in favor of the array form for placement control.
- **Unresolved issues:** Var-name family `drn_searchChopperN` is **shared with `CreateSearchChopper.sqf`** (same base) — both increment separate counters (`drn_CreateDropChopper_CurrentInstanceNo` vs the probe in CreateSearchChopper), so two different instances could in principle receive the same global name and clobber each other. Low probability, but a real latent aliasing bug across the two scripts. Only one turret gunner despite many transport helis having FFV seats.
- **Reforger port notes:** Enfusion helicopter insertion: use a prefab heli + AI pilot behavior + a "fast-rope/para drop" action. The publicVariable + `call compile format` naming is not portable. Model the crew/cargo split with group handles.

### CreateMotorizedSearchGroup.sqf  —  `Code/Scripts/Escape/CreateMotorizedSearchGroup.sqf`
- **Purpose:** Spawns a ground vehicle full of infantry (a "motorized search group") sized by enemy frequency, then hands the vehicle to `drn_fnc_MotorizedSearchGroup` to drive and search the last-known-position marker.
- **Inputs:** `_this = [_spawnPos, _searchAreaMarker, _enemyFrequency, (_minSkill=0.3), (_maxSkill=0.6), (_debug=false)]`.
- **Outputs:** Spawns a crewed vehicle via `BIS_fnc_spawnVehicle`, creates 2–N cargo infantry, sets ranks/leader, applies spawn hook, then `spawn drn_fnc_MotorizedSearchGroup`.
- **Calls:** `BIS_fnc_getCfgData`, `BIS_fnc_spawnVehicle`, `a3e_fnc_onVehicleSpawn`, `drn_fnc_Escape_OnSpawnGeneralSoldierUnit`, `drn_fnc_MotorizedSearchGroup` (a `Code/functions/DRN/` function), `drn_fnc_CL_ShowDebugTextAllClients`. Reads globals `a3e_arr_Escape_MotorizedSearchGroup_vehicleClasses`, `a3e_arr_Escape_InfantryTypes`, `A3E_VAR_Side_Opfor`.
- **Called by:** `execVM "Scripts\Escape\CreateMotorizedSearchGroup.sqf"` from `EscapeSurprises.sqf:131` (the `MOTORIZEDSEARCHGROUP` surprise). Live.
- **Processing:** Server-only. Random vehicle class; reads its `transportSoldier` cargo capacity from config (defaults to 4 if not a number). Spawns vehicle+crew via `BIS_fnc_spawnVehicle`, sets crew rank PRIVATE. Soldier count: full cargo by default, or `2 + random(cargo-3)` at frequency 1, `4 + random(cargo-3)` at frequency 2. Creates cargo infantry (random `a3e_arr_Escape_InfantryTypes`), moveInCargo, rank LIEUTENANT. Selects the first cargo soldier as group leader. Applies spawn hook to all. `spawn drn_fnc_MotorizedSearchGroup`.
- **Theory of operation:** A recurring wheeled patrol that converges on where players were last seen (the `drn_searchAreaMarker`). The MotorizedSearchGroup DRN function does the driving/searching; this is just population.
- **Whys & questions:** The `EGG_EVO_skill` skill calls are commented out (lines 52, 63) — skill now comes entirely from the spawn hook. `_index`, `_soldiersCount` fallbacks reflect defensive coding around modded vehicles with odd `transportSoldier` values.
- **Unresolved issues:** At frequency 1/2 with a small vehicle, `_vehicleMaxCargo - 3` can be ≤0, making `floor random(negative)` return 0 or a negative floor — soldier count could be as low as 2 (freq 1) which is intended, but the arithmetic is fragile for cargo < 3. `_group selectLeader (_insurgentSoldiers select 0)` will error if `_soldiersCount` computed to 0 (empty array) — unlikely but unguarded.
- **Reforger port notes:** Enfusion motorized patrol: prefab vehicle + AI group + search/patrol waypoint on the last-known-position marker. Replace `BIS_fnc_spawnVehicle` and config `transportSoldier` lookup with Reforger prefab seat counts.

### CreateReinforcementTruck.sqf  —  `Code/Scripts/Escape/CreateReinforcementTruck.sqf`
- **Purpose:** Spawns a troop truck with a separate cargo infantry group and dispatches it via `drn_fnc_InsertionTruck` to drive to the search area, drop the troops, and spawn them a search group.
- **Inputs:** `_this = [_spawnPos, (_minSkill=0.3), (_maxSkill=0.6), (_enemyFrequency=3), (_debug=false)]`.
- **Outputs:** Spawns crewed truck via `BIS_fnc_spawnVehicle` (unique var name `drn_ReinforcementTruckVehicleN`), creates a separate `_cargoGroup` of infantry loaded as cargo, then `spawn drn_fnc_InsertionTruck` with an `_fnc_OnDroppingGroup` that starts a SearchGroup.
- **Calls:** `BIS_fnc_getCfgData`, `BIS_fnc_spawnVehicle`, `a3e_fnc_onVehicleSpawn`, `drn_fnc_Escape_OnSpawnGeneralSoldierUnit`, `drn_fnc_InsertionTruck` (DRN), `drn_fnc_SearchGroup` (via callback), `drn_fnc_CL_ShowDebugTextAllClients`. Reads `a3e_arr_Escape_ReinforcementTruck_vehicleClasses`, `a3e_arr_Escape_InfantryTypes`, `A3E_VAR_Side_Opfor`, `drn_searchAreaMarkerName`.
- **Called by:** `execVM "Scripts\Escape\CreateReinforcementTruck.sqf"` from `EscapeSurprises.sqf:334` (the `REINFORCEMENTTRUCK` surprise). Live.
- **Processing:** Server-only. Random truck class + cargo-capacity config read (fallback 4). Spawn truck+crew, find free var name, set crew rank PRIVATE. Cargo group `_cargoGroup` on OPFOR side; soldier count `_enemyFrequency + 3 + random(4*freq)`, clamped to vehicle cargo. Create cargo infantry (LIEUTENANT), moveInCargo. Apply spawn hook to `units _group` (**note: the crew group, not `_cargoGroup`** — see issues). `spawn drn_fnc_InsertionTruck` with drop marker and the search-group callback.
- **Theory of operation:** The ground equivalent of the drop chopper — periodic reinforcements that dismount near the search area and hunt. `drn_fnc_InsertionTruck` drives, unloads at the drop marker, and fires the callback that converts cargo into a `drn_fnc_SearchGroup`.
- **Whys & questions:** Two distinct groups exist — the truck's own crew (`_group` from `BIS_fnc_spawnVehicle`) and `_cargoGroup` (the passengers). The `InsertionTruck` call passes `_cargoGroup` as the group to drop, correct.
- **Unresolved issues:** The spawn-hook `foreach units _group` (line 71) applies to the **crew** group only; the `_cargoGroup` passengers get the hook only individually at creation (line 68) — verify passengers actually receive `A3E_fnc_onEnemySoldierSpawn`. They do (line 68 applies it per-soldier), so this is fine, but the naming is confusing. `EGG_EVO_skill` calls commented out (60, 70). Shared counter/name family with other DRN truck scripts.
- **Reforger port notes:** Same as MotorizedSearchGroup — prefab truck + AI group + drive-to-marker + dismount-and-search behavior. The InsertionTruck driving/unload logic lives in the DRN category and should be ported alongside.

### CreateSearchChopper.sqf  —  `Code/Scripts/Escape/CreateSearchChopper.sqf`
- **Purpose:** Creates a manned search helicopter (crew + FFV turret gunners), turns its light on, and runs `drn_fnc_SearchChopper` so it patrols/searches the last-known-position marker with search/refuel timers.
- **Inputs:** `_this = [_homePos, _side, _searchAreaMarker, (_searchTimeMin=15), (_refuelTimeMin=10), (_minSkill=0.3), (_maxSkill=0.6), (_unitArray=[]), (_debug=false)]`. Docblock header at top of file documents these.
- **Outputs:** Spawns a random chopper from `a3e_arr_searchChopper` at `_homePos + [0,0,100]` (FLY), crews it via `createVehicleCrew`, populates non-locked turrets with infantry, unlocks it, names it `drn_searchChopperN`, turns light on, then `spawn drn_fnc_SearchChopper`.
- **Calls:** `a3e_fnc_onVehicleSpawn`, `createVehicleCrew`, `drn_fnc_Escape_OnSpawnGeneralSoldierUnit`, `drn_fnc_SearchChopper` (DRN); engine `fullCrew`, `lockedTurret`, `moveInTurret`. Reads `a3e_arr_searchChopper`, `a3e_arr_Escape_InfantryTypes`, `a3e_arr_Escape_InfantryTypes_Ind`, `A3E_VAR_Side_Opfor`.
- **Called by:** `execVM "Scripts\Escape\CreateSearchChopper.sqf"` from `Code/functions/Server/fn_initServer.sqf:451` (with a `waitUntil scriptDone` right after). This is **after** the `if(false)` dead-code block closes at line 441, so it is **LIVE** — one search chopper is created at mission init. Also re-implemented inline (not via this script) inside `EscapeSurprises.sqf`'s `RUSSIANSEARCHCHOPPER` surprise.
- **Processing:** Server-only. Optional debug sideChat. Finds a free `drn_searchChopperN` var name. Picks random chopper type; offsets home pos up 100m; `createVehicle [... ,"FLY"]`; runs vehicle-spawn hook; `createVehicleCrew`; applies spawn hook to all crew. Populates FFV turrets: iterates `fullCrew [_chopper,"turret",true]` filtered to FFV-capable turrets (`_x#4`) mapped to turret paths (`_x#3`); for each unlocked turret creates a soldier (Ind vs Opfor class list by side) and `moveInTurret`. Unlocks (`lock 0`), names, binds global, `action ["lightOn"]`, then `spawn drn_fnc_SearchChopper`.
- **Theory of operation:** A persistent hunting helicopter that orbits the search marker between refuels. The FFV-turret population is a modern touch (uses `fullCrew` FFV flags) added over the older base script. `drn_fnc_SearchChopper` handles the search/refuel state machine.
- **Whys & questions:** Multiple commented-out spawn approaches (`BIS_fnc_spawnVehicle`, hard-coded `RHS_Mi8AMTSh_vvsc`) show iteration on how to place the chopper. The FFV block is the notable "live-and-maintained" part vs. the DROPCHOPPER/reinforcement scripts.
- **Unresolved issues:** **`drn_searchChopperN` name family shared with `CreateDropChopper.sqf`** (aliasing risk noted there). At init, only one is created and the drop choppers use `drn_CreateDropChopper_CurrentInstanceNo` starting at 0, so `drn_searchChopper1` (this script's probe starts at 1) vs `drn_searchChopper0` (drop chopper) — they partially avoid collision by different start indices, but it is coincidental, not guaranteed. The RUSSIANSEARCHCHOPPER surprise in EscapeSurprises does **not** reuse this script (duplicated logic — maintenance hazard).
- **Reforger port notes:** Enfusion: prefab attack/transport heli + AI aircrew + orbit/search behavior + fuel model. FFV turret population maps to prefab turret slots. The search/refuel loop (`drn_fnc_SearchChopper`) is the real logic to port.

### DropChopper.sqf  —  `Code/Scripts/Escape/DropChopper.sqf`
- **Purpose:** Flies the drop chopper to the drop position, para-ejects each cargo unit (giving them a parachute backpack at altitude), fires the on-dropped callback, then flies back and self-deletes the chopper + crew.
- **Inputs:** `_this = [_chopper, _dropUnits, _dropPosition, (_onGroupDropped={}), (_debug=false)]`. `_chopper` must have a `vehicleVarName`.
- **Outputs:** Sets chopper vars `waypointFulfilled` / `missionCompleted`; ejects and repositions each drop unit; adds `B_parachute` backpack; runs `_onGroupDropped [_dropGroup, _dropPosition]`; deletes the chopper and its crew at the end.
- **Calls:** `_onGroupDropped` (caller-supplied; in practice starts `DRN_fnc_SearchGroup`); engine `addWaypoint`, `action ["eject"]`, `addBackPackGlobal`, `deleteVehicle`. No CommonLib in the live path (debug branches use `player sideChat`).
- **Called by:** `execVM "Scripts\Escape\DropChopper.sqf"` from `CreateDropChopper.sqf:64`. Transitively live via the DROPCHOPPER / DROPCHOPPER_I surprises.
- **Processing:** Server-only. Reads `group _chopper`. Exits (after 5s) if chopper unnamed. Initializes `waypointFulfilled`/`missionCompleted` false. Spawns a worker thread: waits for `waypointFulfilled`, then loops over `_dropUnits` — removeBackpack, unassignVehicle, `action ["eject"]`, set direction/position ~5m below chopper, and spawns a per-unit descent thread that waits until the unit falls below `85+random 10` metres then adds a parachute backpack (the steerable-parachute createVehicle path is commented out). After ejecting all, recomputes the drop group, calls `_onGroupDropped`, waits for `missionCompleted`, then deletes crew and chopper. Meanwhile the main thread: (optional debug smoke), `flyInHeight 250`, engine on, climb to 100m, add MOVE waypoint to `_dropPosition` (statement sets `waypointFulfilled`), then a second MOVE waypoint back to spawn (statement sets `missionCompleted`).
- **Theory of operation:** Two-phase choreography via chopper variables: waypoint 1 arrival ⇒ `waypointFulfilled` ⇒ eject; waypoint 2 arrival (return) ⇒ `missionCompleted` ⇒ cleanup. Units free-fall then auto-chute near the ground for a fast combat insertion.
- **Whys & questions:** The parachute is a **backpack** (`B_parachute`) added at low altitude rather than a steerable-parachute vehicle (that code is commented out) — simpler, avoids AI-in-parachute pathing issues. The 5m-below reposition prevents rotor collision on eject.
- **Unresolved issues:** `_dropUnit` is used inside the ejection `for` loop but not declared `private` in the worker's `private[...]` list (line 26) — it leaks to the enclosing spawn scope; harmless here (single writer) but sloppy. If the chopper is destroyed mid-flight, `missionCompleted` may never be set and the cleanup thread blocks forever (leaked scripted thread + wreck) — no death/abort guard. `player sideChat` debug on the server is a likely no-op.
- **Reforger port notes:** Enfusion: heli flies waypoints, AI paradrop action (Reforger has parachute entities/animations). Replace variable-flag choreography with waypoint-completion events / behavior states. Add an abort path on chopper death to avoid the stuck-cleanup issue.

### EscapeSurprises.sqf  —  `Code/Scripts/Escape/EscapeSurprises.sqf`
- **Purpose:** The master "surprises" scheduler — the escalating-pressure engine of the mission. Builds a list of timed events (drop choppers, search chopper, search drone, leaflet drone, motorized group, reinforcement truck, civilian enemy) and, in an infinite loop, fires each when its time arrives, then re-schedules a fresh instance of itself.
- **Inputs:** `_this = [_minEnemySkill, _maxEnemySkill, _enemyFrequency, (_debug=false)]`. Waits for `drn_searchAreaMarkerName` marker to exist. Reads many global class/array pools (`a3e_arr_O_transport_heli`, `a3e_arr_O_pilots`, `a3e_arr_I_*`, `a3e_arr_O_attack_heli`, `a3e_arr_searchdrone`, `a3e_arr_leafletdrone`, `A3E_arr_recon_InfantryTypes`, `a3e_arr_recon_I_InfantryTypes`, `a3e_arr_Escape_EnemyCivilianCarTypes`, `A3E_VAR_Side_*`, `A3E_Debug`).
- **Outputs:** Continuously execVMs/spawns the create-scripts and drone/chopper functions; creates helis/drones directly for RUSSIANSEARCHCHOPPER/SEARCHDRONE/LEAFLETDRONE; logs every scheduled surprise via `diag_log`.
- **Calls:** `drn_fnc_CL_MarkerExists`, `drn_fnc_CL_GetRandomMarkerPos`, `A3E_fnc_FindSpawnRoad`, `A3E_fnc_GetPlayerGroup`, `a3e_fnc_onVehicleSpawn`, `drn_fnc_Escape_OnSpawnGeneralSoldierUnit`, `DRN_fnc_SearchGroup`, `DRN_fnc_SearchChopper`, `A3E_fnc_SearchDrone`, `A3E_fnc_LeafletDrone`, `bis_fnc_spawnvehicle`. execVMs `CreateMotorizedSearchGroup.sqf`, `CreateDropChopper.sqf`, `CreateReinforcementTruck.sqf`, `CreateCivilEnemy.sqf`.
- **Called by:** `execVM "Scripts\Escape\EscapeSurprises.sqf"` from `Code/functions/Server/fn_initServer.sqf:214` (before the `if(false)` block). **Live — this is the mission's core dynamic-threat driver.**
- **Processing:** Server-only. Waits for the search marker. Builds `_surprises`, each `[ID, fireTimeSec, condition, isExecuted, args]`; fire times are `time + base*(0.5 + (4-freq)/4)` so higher frequency ⇒ sooner. SEARCHDRONE and LEAFLETDRONE are only added if their class pools are non-empty (leaflet also if the var is nil). Then an outer `while{true}` (60s sleep) scans all surprises; for each not-yet-executed one whose time passed and whose `condition` holds, marks it executed, dispatches the matching branch (a big `if (_surpriseID == ...)` cascade), and **appends a fresh re-scheduled surprise of the same type** so the threat recurs indefinitely.
- **Theory of operation:** A self-perpetuating event queue: rather than looping fixed timers, each firing enqueues its own successor with a new randomized delay, producing an endless, frequency-scaled stream of reinforcements/search assets. The `condition` (usually "search marker exists") gates events on players having been detected.
- **Whys & questions:** Each branch inlines the spawn logic (creating groups, choosing heli/pilot types from the pools) rather than always delegating to a Create-script — RUSSIANSEARCHCHOPPER/SEARCHDRONE/LEAFLETDRONE are fully inline, duplicating logic that could reuse `CreateSearchChopper.sqf`. The re-schedule delays differ subtly between the initial build and the in-loop rebuild (e.g. MOTORIZEDSEARCHGROUP uses `time + base*(4-freq)` on rebuild, a different formula than the initial). Many `EGG_EVO_skill` calls are commented out throughout.
- **Unresolved issues:** `_surprises` grows unbounded (every firing appends a new entry; old executed entries are never removed), so the inner `foreach` scans an ever-lengthening list — a slow memory/CPU leak over very long sessions. The `MOTORIZEDSEARCHGROUP` rebuild formula `time + _timeInSek * (4 - _enemyFrequency)` differs from every other branch's `*(0.5 + (4-freq)/4)` — likely an inconsistency/bug (at freq 4 it yields `time + 0`, i.e. immediate re-fire). Candidate BUG. The leaflet-drone guard `count(...)>0 || isNil "a3e_arr_leafletdrone"` will schedule leaflet drones even when the array is undefined (falls back to `I_UAV_06_F`).
- **Reforger port notes:** This is the single most important behavioral spec to port. Re-express as an Enfusion server-side threat-director (a `GameMode` component or scripted manager) with a scheduled event queue. Fix the unbounded-list growth (remove executed entries or use a proper timer/scheduler). Frequency scaling and per-type cooldowns carry over as tunable data.

### SearchLeader.sqf  —  `Code/Scripts/Escape/SearchLeader.sqf`
- **Purpose:** The **old** monolithic "search leader" AI-director: detects when OPFOR/Independent units spot a player, has the spotter "report to HQ" after a delay, then reveals the player to nearby enemies, drops a last-known-position marker, orders searches, and can call artillery/CAS on the last-known position.
- **Inputs:** `_this = [_searchAreaMarkerName]`. Reads `a3e_var_knownPositionHelperObject`, `a3e_var_knownPositionMinDistance`, `A3E_Param_Artillery`, `a3e_var_artillery*`, `A3E_VAR_Side_*_Str`, `A3E_Debug`, and mission player helpers.
- **Outputs:** Creates world-sized detection triggers; sets `a3e_var_SearchLeader_Detected`; creates the search-area marker (local) and last-known-position helper objects; spawns `A3E_fnc_watchKnownPosition` and `a3e_fnc_OrderSearch`; calls `a3e_fnc_FireArtillery` / `a3e_fnc_CallCAS`.
- **Calls:** `A3E_fnc_GetPlayers`, `A3E_fnc_GetPlayerGroup`, `A3E_fnc_watchKnownPosition`, `a3e_fnc_OrderSearch`, `a3e_fnc_FireArtillery`, `a3e_fnc_CallCAS`; engine `createTrigger`, `nearTargets`, `knowsAbout`, `reveal`, `findNearestEnemy`.
- **Called by:** **Nothing live.** Its call site is explicitly commented out and labeled deprecated: `//[drn_searchAreaMarkerName, A3E_Debug] execVM "Scripts\Escape\SearchLeader.sqf"; //depreciated` at `Code/functions/Server/fn_initServer.sqf:236`. The line immediately below (`237: [] call A3E_fnc_SearchleaderInit;`) is the live replacement.
- **Processing:** Server-only. Sets up two map-covering `EmptyDetector` triggers (Blufor detecting Opfor/Ind) that flip `a3e_var_SearchLeader_Detected`. A spawned thread additionally flags detection if a civilian within 300m of a player is "reporting." - **Reforger port notes:** Do **not** port this file. Port the live `Code/functions/SearchLeader/` category instead (documented in [SearchLeader.md](SearchLeader.md)).
