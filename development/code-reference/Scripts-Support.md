### CommonLib.sqf  —  `Code/Scripts/DRN/CommonLib/CommonLib.sqf`
- **Purpose:** The DRN "CommonLib" utility library (Engima of Ostgota Ops, v1.04, 2011). Defines the global `drn_fnc_CL_*` helper functions — markers, positions, on-screen text, scoring, garbage collection, debug text/markers — that the mission's `Code/functions/DRN/*` (and several `Server`/`AI` extraction/drone functions) depend on. Documented as **one entry** summarizing the library; the key functions are catalogued below rather than one field each.
- **Inputs:** None on load — it is a definitions file. Reads config at load: `missionConfigFile >> "Params"` (in `drn_fnc_CL_InitParams`). Individual functions take their own args (marker names, positions, units, text). Reads the global `A3E_Debug` in the garbage-collector / debug helpers.
- **Outputs:** Defines ~21 global `drn_fnc_CL_*` code variables plus supporting globals: `a3e_var_CL_SilentDebugMode`, `a3e_var_CL_CommonLibVersion = 1.04`, and the sentinel **`a3e_var_commonLibInitialized = true`** (set on the last line — used elsewhere as the "CommonLib is loaded" guard). Registers three `addPublicVariableEventHandler`s (on `drn_CL_ShowCommandTextEventArgs`, `drn_CL_ShowTitleTextEventArgs`, and the debug-text/marker event-arg globals) so the `*AllClients` wrappers can broadcast to clients via `publicVariable`.
- **Calls:** Internally, the broadcast wrappers call their local counterparts: `*AllClients` → `*Local` (`ShowCommandText`, `ShowTitleText`, `ShowDebugText`, `SetDebugMarker`, `DeleteDebugMarker`); `AddScore` → `AddScoreServer`. Otherwise self-contained (engine commands only: `getMarkerPos`, `createMarkerLocal`, `titleText`, `addScore`, `deleteGroup`, etc.).
- **Called by:** Loaded once, server-side, by `Code/functions/Server/fn_initServer.sqf:5` via `call compile preprocessFileLineNumbers "Scripts\DRN\CommonLib\CommonLib.sqf";`. Its functions are then consumed across the codebase — grep shows `drn_fnc_CL_*` referenced in 22 files under `Code/` (heaviest consumers: the `Code/functions/DRN/*` scripts, plus `Server/fn_RunExtraction*`, `AI/fn_SearchDrone`, `AI/fn_LeafletDrone`, and `Scripts/Escape/*`). Several consumers guard on `a3e_var_commonLibInitialized` / version and `sideChat` a "needs CommonLib v1.02" warning if missing.
- **Processing:** Straight-line file: sets a couple of globals, then assigns each `drn_fnc_CL_*` = `{...}` and registers the three PV event handlers, finishing with the version + `initialized` sentinel. **Function catalogue** (line refs into this file):
  - Markers/positions: `MarkerExists` (49), `GetMarkerWithinRange` (72), `GetClosestMarker` (124), `RotatePosition` (181), `GetRandomMarkerPos` (211), `PositionIsInsideMarker` (258, supports RECTANGLE/ELLIPSE at any angle since v1.01).
  - On-screen text (local + broadcast pairs): `ShowCommandTextLocal`/`AllClients` (313/329), `ShowTitleTextLocal`/`AllClients` (350/373).
  - Scoring: `AddScore` (401) → `AddScoreServer` (391), routed either directly (server) or via `publicVariable "drn_CL_AddScoreEventArgs"`.
  - Garbage collection: `AddUnitsToGarbageCollector` (424) and `RunGarbageCollector` (444).
  - Debug: `ShowDebugTextLocal`/`AllClients` (566/587), `SetDebugMarkerLocal`/`AllClients` (612/693), `DeleteDebugMarkerLocal`/`AllClients` (704/715), plus `InitParams` (22, SP paramsArray defaulting).
- **Theory of operation:** Classic pre-`remoteExec`-era Arma broadcast pattern: a global "event args" variable + `addPublicVariableEventHandler` propagates an effect to every client. `*Local` runs the effect on the caller; `*AllClients` writes the args global and `publicVariable`s it so the registered PV handler re-runs the `*Local` on each machine. The library predates modern Arma 3 idioms (it targets Arma 2 / early A3, hence `param1`/`param2`/`paramsArray`).
- **Whys & questions:** Kept verbatim as a vendored library so the DRN function set (ambient infantry, search groups, military traffic, extraction, drones) still resolves its `drn_fnc_CL_*` calls. Namespacing is inconsistent — some helpers write `a3e_var_*` and read `A3E_Debug`, i.e. it has been lightly patched into the mission's `A3E`/`a3e` namespace over time (mixed `drn_`/`a3e_var_`).
- **Unresolved issues:** **Dead code (candidate RD):** grepping the live `Code/` tree (excluding this file) shows these have **zero external callers and are not called internally**: `InitParams`, `GetMarkerWithinRange`, `GetClosestMarker`, `RotatePosition`, and the whole scoring path `AddScore`/`AddScoreServer`. The garbage collector is effectively inert — `AddUnitsToGarbageCollector`'s body is **entirely commented out** (lines ~428-432) so it does nothing, and `RunGarbageCollector` has only one caller. Externally-live helpers: `GetRandomMarkerPos` (~20 refs), `ShowDebugTextAllClients` (~42), `SetDebugMarkerAllClients` (~20), `MarkerExists` (~18), `DeleteDebugMarkerAllClients` (~17), `PositionIsInsideMarker` (~6), `ShowTitleTextAllClients` (~4), `RunGarbageCollector` (1). The `*Local`/`AddScoreServer` variants show 0 *external* refs but are live via the internal wrappers. **Uncertainty:** counts are grep-based across `Code/**` only — a classname string or `call compile` indirection could hide a use; treat "dead" as high-confidence-but-verify.
- **Reforger port notes:** Do **not** port this file as-is. In Enfusion/Enforce Script the whole PV-event broadcast pattern is replaced by RPC (`Rpc`/`RplComponent`) — reimplement the ~8 genuinely-used helpers (`GetRandomMarkerPos`, `PositionIsInsideMarker`, `MarkerExists`, and the debug text/marker + title-text broadcasts) as typed methods on a mission-support component, and drop the dead scoring/GC/param helpers. Marker helpers assume Arma's named-marker system (`getMarkerPos`, `markerType`) which has no direct Reforger analogue; the port will need its own location/zone data structure.

### dronehack_init.sqf  —  `Code/Scripts/AT/dronehack_init.sqf`
- **Purpose:** Bootstraps the "drone hack" feature on each client: compiles the hack logic, then (per player life) adds the "Hack UAV Terminal" player action.
- **Inputs:** None. Depends on `player`. Relies on `hackdrone.sqf` having been compiled first (it does so itself, line 1).
- **Outputs:** Compiles `Scripts\AT\hackdrone.sqf` (defining the `at_fnc_dh_*` globals). Spawns a thread that waits for a valid `player`, calls `at_fnc_dh_init`, and installs a `"Respawn"` event handler that re-runs `at_fnc_dh_init` on each respawn.
- **Calls:** `at_fnc_dh_init` (from hackdrone.sqf); `preprocessFile` / `compile`.
- **Called by:** `Code/functions/Common/fn_initLocalPlayer.sqf:71` — `call compile preprocessFile "Scripts\AT\dronehack_init.sqf";` (client-local player init).
- **Processing:** (1) compile-load `hackdrone.sqf`; (2) `spawn` a thread → `waitUntil {!isNull player}` → `[] spawn at_fnc_dh_init` → register `player addEventHandler ["Respawn", { [] spawn at_fnc_dh_init }]` so the action is re-added after respawn.
- **Theory of operation:** Player actions are attached to the player object and are lost on death/respawn, so re-registering `at_fnc_dh_init` on the `Respawn` EH keeps the "Hack UAV Terminal" action available across lives.
- **Whys & questions:** The action is added unconditionally (no CBA param gate, unlike magRepack) — so drone-hacking is always on. Presumably intentional as a small player-vs-UAV mechanic.
- **Unresolved issues:** None specific to the bootstrap. See `hackdrone.sqf` for the hard-coded classname lists (maintenance/port risk).
- **Reforger port notes:** Player actions map to Reforger's action/interaction system (`ScriptedUserAction` / interaction components) rather than `addAction`. The respawn-reattach dance is unnecessary if the action lives on a persistent component. Low priority — the whole feature is a niche extra.

### hackdrone.sqf  —  `Code/Scripts/AT/hackdrone.sqf`
- **Purpose:** The drone-hack logic: lets a player who is carrying an *enemy* side's UAV terminal "hack" it by swapping it for their own side's terminal (so they can take control of that faction's UAVs).
- **Inputs:** Invoked via the player action; `_this` from `addAction` is `[target, caller, actionId, args]`. Reads `side` of the acting unit and its `items`.
- **Outputs:** Defines four globals: `at_fnc_dh_init` (sets side/terminal/drone classname arrays and adds the action), `at_fnc_dh_hackUAVTerminal` (the swap), `at_fnc_dh_terminalCheck` (action `condition`), `AT_FNC_dh_Switchmove` (anim helper). Defines the classname config arrays `AT_DH_Sides`, `AT_DH_Terminals`, `AT_DH_DronesPacked`, `AT_DH_Drones`. Side effects: plays a "medic/hacking" animation via `BIS_fnc_MP`, and after a 6s delay `removeItem`s the enemy terminal and `addItem`s the caller's own-side terminal.
- **Calls:** `at_fnc_dh_switchMove` remotely via `BIS_fnc_MP`; engine commands `addAction`, `items`, `removeItem`, `addItem`, `side`.
- **Called by:** All four functions are compiled by `dronehack_init.sqf` (line 1); `at_fnc_dh_init` is spawned from that bootstrap. The action's callback (`at_fnc_dh_hackUAVTerminal`) and condition (`at_fnc_dh_terminalCheck`) fire from the engine action menu.
- **Processing:** `at_fnc_dh_init` populates the side/terminal arrays (index 0=east, 1=west, 2=resistance) and adds the action gated on `at_fnc_dh_terminalCheck`. The check/hack both compute `_sideNumber = AT_DH_Sides find (side _unit)` and iterate `AT_DH_Terminals` (via `forEach`); if the unit holds a terminal whose `_forEachIndex` (side) differs from its own side, it is hackable. On hack: play anim, wait 6s, if still alive swap enemy terminal → own-side terminal.
- **Theory of operation:** Terminals are side-locked in Arma (a BLUFOR terminal only controls BLUFOR UAVs), so "hacking" is modeled as physically converting a captured enemy terminal into the friendly equivalent by classname substitution. The 6s `sleep` + animation is the "hacking in progress" beat.
- **Whys & questions:** Why `BIS_fnc_MP` for the animation rather than a local `switchMove`? Likely so other players see the hacking pose. The side→index mapping is positional and must stay in lockstep across `AT_DH_Sides` / `AT_DH_Terminals` / `AT_DH_Drones`.
- **Unresolved issues:** **Hard-coded vanilla + mod classname lists** (`AT_DH_Terminals` includes `*_lxWS` "Tura"/"FIA" terminals from a specific mod, and only the vanilla `UAV_01` drones/backpacks). On maps/modsets without those classes the feature silently no-ops; new UAVs are not covered (maintenance debt — candidate RD). The `AT_DH_DronesPacked` / `AT_DH_Drones` arrays are defined but appear unused by the hack logic here (only terminals are swapped) — possible dead data (candidate RD, verify). Naming inconsistency: `AT_FNC_dh_Switchmove` (definition) vs `at_fnc_dh_switchMove` (call site) — case-insensitive so fine, style noise per RD-008.
- **Reforger port notes:** Reforger UAV/AI-terminal support is very different from Arma's UAV terminal item model; this feature likely needs a full redesign or may be dropped. If kept, replace the item-swap with a permission/ownership change on the drone entity. Low port priority.

### MagRepack_init_sv.sqf  —  `Code/Scripts/outlw_magRepack/MagRepack_init_sv.sqf`
- **Purpose:** **Third-party mod** — Outlaw's "Mag Repack" (author Outlawled, updated to 3.1.3 by GiPPO, 2015). Bundled into the mission to let players redistribute loose rounds between magazines of the same ammo type via a dialog (default keybind Ctrl+R). This file is the entry point / initializer.
- **Inputs:** None (client-local). Reads player keybinding prefs from `profileNamespace` (`outlw_MR_*_profile`). Self-disables if the mod is present as an addon (`isClass CfgPatches >> "Scripts\outlw_magRepack"`).
- **Outputs:** Sets many `outlw_MR_*` globals (timings, keybinding state, version), `execVM`s the three script files (Main, Keybindings, Misc), computes `outlw_MR_listIDCs` from the mission dialog config, installs a `KeyDown` display event handler on display 46, and prints two `systemChat` init lines.
- **Calls:** `execVM` of `Scripts/outlw_magRepack/Scripts/{MagRepack_Main,MagRepack_Keybindings,MagRepack_Misc}.sqf`; `outlw_MR_getIDCs`, `outlw_MR_keyListToString`, `outlw_MR_keyDown` (all defined in the three sub-scripts).
- **Called by:** `Code/functions/Common/fn_initLocalPlayer.sqf:75-77`, gated: `if (A3E_Param_Magrepack == 1) then { [] execVM "Scripts\outlw_magRepack\MagRepack_init_sv.sqf"; };`. So the whole feature is opt-in via the `A3E_Param_Magrepack` mission parameter.
- **Processing:** define timing/keybinding globals → load prefs from `profileNamespace` → `execVM` the three sub-scripts → `waitUntil` they've defined `outlw_MR_getIDCs` → build the control-IDC list from `MR_Dialog` config → `waitUntil` display 46 exists → attach the KeyDown handler that opens the repack dialog on the bound key.
- **Theory of operation:** Standard self-contained script mod: globals + dialog defs (`MagRepack_Dialog_Main`/`_Keybindings`/`_About`, defined in mission `description.ext`/config) + a keybind that opens the dialog. Repack math lives in `MagRepack_Main.sqf` (`outlw_MR_repack`), helpers/keybinding UI in the other two.
- **Whys & questions:** Bundled rather than required as a client mod so it works on vanilla clients. Uses `BIS_fnc_areEqual` and `profileNamespace` persistence — standard for its era.
- **Unresolved issues:** **Third-party / licensing:** this is external code (Outlawled / GiPPO) vendored into the repo; original license terms are not stated in-file — confirm redistribution rights before shipping the port (candidate RD/Q). Version is pinned to 3.1.3 (2015) and unmaintained here. Minor: `MagRepack_Main.sqf` line ~898 has a typo `}:` (should be `};`) after `outlw_MR_showFullSwitch`'s `if/else` — worth flagging (candidate BUG, low sev; may be tolerated by the parser since it's followed by a statement, but it's malformed).
- **Reforger port notes:** **Light port relevance — likely drop or replace.** It is UI-heavy (`createDialog`, `displayCtrl`, `ctrlSet*`, `lnb*`), all of which is Arma-3 dialog API with no Enfusion equivalent (Reforger UI is the layout/widget system). Magazine handling (`magazinesAmmo`, `addMagazine [type, count]`) also differs. If magazine repacking is desired in Reforger, reimplement natively rather than port. Do not spend effort porting the dialog code.

### MagRepack_Keybindings.sqf  —  `Code/Scripts/outlw_magRepack/Scripts/MagRepack_Keybindings.sqf`
- **Purpose:** **Third-party.** The keybinding-configuration dialog for Mag Repack: lets the player rebind the open key and modifiers (Shift/Ctrl/Alt), and persists the choice.
- **Inputs:** UI events from the `MagRepack_Dialog_Keybindings` dialog; reads current binding from the `outlw_MR_*` globals.
- **Outputs:** Defines `outlw_MR_openKeybindings`, `outlw_MR_applyKeybinding`, and the `outlw_KB_*` UI helpers (`keyDown`, `enableApply`, `updateKeyText`, `modifierSwitch`). Writes the new binding to `outlw_MR_keyList` and persists to `profileNamespace ["outlw_MR_keyList_profile", ...]`.
- **Calls:** engine dialog commands (`createDialog`, `displayCtrl`, `ctrlEnable`, `ctrlSetBackgroundColor`, `keyName`), `BIS_fnc_areEqual`, `outlw_MR_keyListToString` (Misc).
- **Called by:** `execVM`'d by `MagRepack_init_sv.sqf:49`. Its functions are triggered from the options section of the main dialog and from the keybindings dialog's controls.
- **Processing:** `openKeybindings` builds/pre-fills the dialog from current binding; `modifierSwitch` toggles Shift/Ctrl/Alt highlight state; `keyDown` captures the new key; `enableApply` enables the Apply button only when the binding changed; `applyKeybinding` commits + persists (or resets to default).
- **Theory of operation:** Small stateful UI form over the `outlw_MR_keyList` `[shift, ctrl, alt, keycode]` tuple, persisted in `profileNamespace`.
- **Whys & questions:** Standard for the mod; nothing mission-specific.
- **Unresolved issues:** Same third-party/licensing note as the init file.
- **Reforger port notes:** Reforger has a native keybinding/input-action system (`.conf` input actions) — a port would use that instead of a custom rebind dialog. Do not port. Light relevance.

### MagRepack_Main.sqf  —  `Code/Scripts/outlw_magRepack/Scripts/MagRepack_Main.sqf`
- **Purpose:** **Third-party.** The core of Mag Repack: the main dialog and the actual round-transfer ("repack") logic between a chosen Source and Target magazine, plus the debug/diff report.
- **Inputs:** UI events from `MagRepack_Dialog_Main`; reads `magazinesAmmo player`, `CfgMagazines` config (count, ammo, displayName, picture), and `outlw_MR_*` state globals.
- **Outputs:** Defines the big `outlw_MR_*` UI/logic functions: `createDialog`, `populateMagListBox`/`populateMagComboBox`, `filter`, `hideFull`, `repack`, `repackingText`, `debugInfo`, `block`, `onDrag`/`onMouseButtonUp`, `sourceEnabled`/`targetEnabled`, `addSource`/`clearSource`, `addTarget`/`clearTarget`, `moveToList`, `optionsMenu`, `debugSwitch`, `showFullSwitch`, `onDialogDestroy`. Mutates the player's magazines (`addMagazine`/`removeMagazine`) as rounds are moved; applies a `DynamicBlur` PP effect while the dialog is open.
- **Calls:** Misc helpers (`outlw_MR_magInfo`, `magVerified`, `removeMag`, `isBeltMagazine`, `isConvertable`, `getConversion`, `ctrlSetPos`, `shortString`, `uniqueMags`, `filter`), Keybindings (`openKeybindings`), and many engine dialog/magazine commands.
- **Called by:** `execVM`'d by `MagRepack_init_sv.sqf:48`. `createDialog` is invoked from `outlw_MR_keyDown` (Misc) on the bound key.
- **Processing:** `createDialog` builds the dialog, plays a stance animation, populates the mag list/combo, and spawns a watcher loop that re-populates the list whenever `magazinesAmmo player` changes or the player dies. `repack` runs a timed loop (`outlw_MR_bulletTime` per bullet / `outlw_MR_beltTime` per belt) moving rounds from Source to Target, updating progress bars, and clearing Source/Target when depleted/full. `onDialogDestroy` returns any in-flight rounds to the player and, in debug mode, `hint`s a before/after ammo diff.
- **Theory of operation:** Source/Target are lifted out of the player's inventory (`removeMag`), tracked as plain counts while the timed loop shuttles rounds between them, then written back (`addMagazine [type, count]`). Belt magazines (MG/≥100-round) transfer in one chunk; box mags transfer per-bullet.
- **Whys & questions:** GiPPO's 1.48 notes in-file explain a switch from a draggable `lnb` (list-n-box) to a plain listbox because ListNBox became non-draggable in that Arma 3 build — good historical context, irrelevant to Reforger.
- **Unresolved issues:** **Typo:** line ~898 ends `outlw_MR_showFullSwitch`'s `if/else` with `}:` instead of `};` (stray colon) — malformed SQF (candidate BUG, low sev). Same third-party/licensing note.
- **Reforger port notes:** Entirely Arma-3 dialog + inventory API — no direct Enfusion mapping. If repacking is wanted in Reforger, reimplement against Reforger's inventory/magazine system and UI. Do not port. Light relevance.

### MagRepack_Misc.sqf  —  `Code/Scripts/outlw_magRepack/Scripts/MagRepack_Misc.sqf`
- **Purpose:** **Third-party.** Supporting/utility functions for Mag Repack: the keydown dispatcher, magazine inventory queries, magazine "convertibility" (e.g. 1Rnd ↔ 3Rnd grenade rounds), string/IDC helpers, and the About dialog.
- **Inputs:** `_this` per function (KeyDown args, magazine type strings, control IDCs); reads `magazinesAmmo player` and `CfgMagazines`.
- **Outputs:** Defines `outlw_MR_modifierCheck`, `outlw_MR_keyDown`, `outlw_MR_getIDCs`, `outlw_MR_isAnimating`, `outlw_MR_ctrlSetPos`, `outlw_MR_shortString`, `outlw_MR_ammoDisplayName`, `outlw_MR_magInfo`, `outlw_MR_removeMag`, `outlw_MR_magVerified`, `outlw_MR_uniqueMags`, `outlw_MR_isBeltMagazine`, `outlw_MR_isConvertable`, `outlw_MR_getConversion`, `outlw_MR_convert`, `outlw_MR_keyListToString`, `outlw_MR_openAbout`. Mutates player magazines in `removeMag`/`convert`.
- **Calls:** engine config/inventory/string commands; `getConversion` (self); dialog helpers.
- **Called by:** `execVM`'d by `MagRepack_init_sv.sqf:50`. `outlw_MR_getIDCs` and `outlw_MR_keyListToString` are awaited/used by the init file; `keyDown` is the display-46 KeyDown handler; the rest are called from Main/Keybindings.
- **Processing:** `keyDown` matches the pressed key+modifiers against the saved binding and opens/closes the dialog (also handles the Shift+Ctrl+Alt+Backspace reset). `magInfo` builds parallel arrays of mag types/counts/caps for the player's repackable mags. `getConversion`/`isConvertable`/`convert` implement magazine conversion (grenade/UGL round count transforms). `getIDCs` recursively walks the dialog config to collect control IDCs (used by `isAnimating`). String helpers truncate/clean display names.
- **Theory of operation:** Pure helper layer over `magazinesAmmo`/`CfgMagazines`; the "parallel arrays" `[types, counts, caps, ...]` convention threads through Main.
- **Whys & questions:** Conversion logic special-cases `count == 3` mags and a leading `"1"` → `"3"` classname char swap, plus a `"3Rnd_" + type` fallback — heuristic, mod-classname-dependent.
- **Unresolved issues:** Same third-party/licensing note. Conversion heuristics are fragile against non-standard magazine classnames (would silently no-op).
- **Reforger port notes:** Helper logic is Arma-inventory-specific; no direct port. Light relevance — see the other magRepack entries.
